## 修改一：二维码内嵌访问密码

**文件**：`lib/service.mjs`

新增 `qrTextFor(base, host)` 函数（位于工厂函数体内、`return {` 之前），
并修改 `status()` 中的二维码文本来源：

```js
// 原版
lanQr:    await qrCached(lanUrl),
tunnelQr: await qrCached(tunnel?.url ?? null),

// 修改后
lanQr:    await qrCached(qrTextFor(lanUrl, lan)),
tunnelQr: await qrCached(qrTextFor(tunnelUrl, tunnelHost)),
```

受密码保护的入口会在二维码里追加 `?token=<PIN>`，使扫码一次直达。
该参数是 proxy 自身支持的通道（`lib/proxy.mjs` 的 `authCheck`），
命中后种下 HttpOnly cookie；随后该 query 会被换成 launch token 走握手，两者不冲突。
局域网未开启密码保护时行为与原版一致。

## 修改二：新增 `/dsh-pocket/entry.json` 端点

**文件**：`lib/service.mjs`、`lib/index.js`

- `lib/service.mjs`：在返回对象中新增 `async entryInfo()`，返回
  `{ lanUrl, publicUrl, publicPin }`。
- `lib/index.js`：在 `disposers.push(disposeRpc)` 之后注册只读路由
  `ctx.webServer.register({ kind: 'exact', path: '/dsh-pocket/entry.json', ... })`。

用途见「安装说明-必读.txt」。该路由挂在 DSH 自身的 webServer 上、经代理转发，
公网入口的请求在代理层仍需先通过密码校验，不会向外网泄露密码。

## 修改三（已取消）：修复公网隧道自动恢复失效

**文件**：`lib/index.js`

```js
// 原版
home: internals.home,

// 修改后
home: internals.home ?? (process.env.DSH_HOME ?? join(homedir(), '.dsh')),
```

生产环境下 DSH 调用 `apply(ctx, config)` 不传第三参数，`internals` 恒为 `{}`，
于是 `home` 恒为 `undefined` → `service.mjs` 中
`autoStatePath = home ? join(...) : null` 得到 `null` →
`persistAutoTunnel()` 与 `restoreTunnelIfNeeded()` 双双成为空操作。
即上游「公网隧道自动恢复」功能实际从未生效：标记文件从不落盘，
DSH 重启后隧道也不会恢复。

## 修改三：Windows 上开启公网不再弹出控制台窗口

**文件**：`lib/tunnel.mjs`（`startNamedTunnel` 与 `startQuickTunnel` 两处 `spawn`）

```js
// 原版
const child = spawn(bin, ['--no-autoupdate', 'tunnel', '--url', `http://127.0.0.1:${port}`, '--protocol', 'http2'], {
  stdio: ['ignore', 'pipe', 'pipe'],
  env: cloudflaredEnv(),
});

// 修改后
const child = spawn(bin, ['--no-autoupdate', 'tunnel', '--url', `http://127.0.0.1:${port}`, '--protocol', 'http2'], {
  stdio: ['ignore', 'pipe', 'pipe'],
  env: cloudflaredEnv(),
  windowsHide: true,
});
```

`cloudflared.exe` 是 **控制台子系统（CUI）** 程序，而 DSH 宿主本身是无控制台的分离进程
（`MainWindowHandle = 0`，不拥有任何窗口）。子进程没有可复用的控制台，Windows 就会为它
**新建一个可见的控制台窗口** —— 这就是点「打开公网」时冒出来的那个黑框（在 Windows 11 上
由 Windows Terminal 承载，标题就是 `cloudflared.exe` 的路径）。

那个窗口不是装饰：它就是这个进程的控制台。**关掉窗口 = 向 cloudflared 发 CTRL_CLOSE**，
隧道进程随即退出，界面报「开启失败：隧道进程退出（code=0）」，二维码域名立刻失效。

补 `windowsHide: true` 后，子进程用隐藏窗口的控制台创建，既不弹窗也不会因为"没人去关它"
而意外终止。该选项只对 Windows 生效，其它平台无副作用；上游 `lib/service.mjs` 的
`execFile` 已经在用 `windowsHide: true`，这里属于同类疏漏。

**实测（本机 Windows 11 / Node 24.17 / cloudflared 2026.9.1）**：

| | 新增可见窗口 | 隧道结果 |
|---|---|---|
| 原版 | 1 个（`CASCADIA_HOSTING_WINDOW_CLASS` + `PseudoConsoleWindow`，标题为 cloudflared.exe 路径） | 可连，但关窗即退出 |
| 加 `windowsHide` | 0 个 | 可连（`Registered tunnel connection`） |

**同一原因导致的另两处闪窗，一并补上**（不弹主界面，只在点「重启」「更新插件」时一闪）：

- `lib/restart.js`：`restartHost()` 里 `spawnFn(process.execPath, ['-e', helperCode(...)], { detached: true, stdio: 'ignore', env })`
  加 `windowsHide: true`。
- `lib/index.js`：`performUpdate()` 里 `spawn('dsh', [...], { ..., shell: true })` 加 `windowsHide: true`
  —— `shell: true` 在 Windows 上会拉起 `cmd.exe`（同样是 CUI 程序）。
